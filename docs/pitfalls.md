# 已知陷阱（真踩过的）

> 这是**参考清单**，不是规范。规范在 `AGENTS.md`；长期目标在 `ROADMAP.md`。
> 每条的「真因」是排查起点：出现同样症状时先按这一列核对，能省很多时间。

| 症状 | 真因 |
|---|---|
| 全自动挂机黑屏（HUD 正常、画面全黑） | `Input.mx = clampM(v, window.W)` → `window.W` 是 undefined → NaN 进相机。用 `GW()/GH()` + NaN 防护 |
| **整页黑屏（从加载起就没有画面，连 intro 都没有；零异常、零 NaN）** | 三层叠加：① 上游页是真 SDK，kv 走 postMessage 问宿主，镜像里没人应答 → `storeLoad` 无限重试；② `DzmmHost.create()` 之后必须用 `mount()`——否则宿主的 `send()` 指向 null，`dzmm:ready` 静默失效；③ `platform.js` 用相对路径 `js/…` 二次加载 45 个脚本，在 `upstream/` 布局下全 404 → `Promise.all` 拒绝 → **跳过 `EMBER_START()`**（渲染循环永不点火）。修法：入口页 `DzmmHost.create()+mount()` 当宿主，检测「加载失败」横幅后补调一次 `EMBER_START()`（`__emberKicked` 防双循环）。注意 77 个静态 `../js/` 标签早已把全部脚本载入——「launchRun 存在但屏幕全黑」即此症 |
| 挂机完全不动 | `A._pickTries` 未初始化却在 drive 里访问 → 每帧抛错 |
| 面板后半截功能全失效（AI 设置/指令台消失） | `bench.js` 语法错误（重复形参）→ 整个文件不加载 → `TSW.bench` undefined → `panel.js` 中途抛错 |
| 面板按钮全点不动 | 事件拦截写在 **capture** 阶段；必须用冒泡 |
| 首局机制提示弹窗不消失、模拟冻结 | 每帧 `tap('Enter')` → 沿用 `pressed` 只触发一次；用边沿安全 tap |
| fullrun 静默卡死、无任何报错 | `dashSafe` 里逐采样点调完整 `hazardAt`（含 `G.foeFx`/`G.zones` 遍历）→ 每帧计算量爆炸 |
| 原地转圈 | 只靠「到目标直线距离」判进度（绕墙时距离变大 → 误判）；要用路标推进 |
| 在已用尽的交互物旁反复横跳 | 目标扫描漏了 `it.used`；已拿走的武器/已开的箱仍留在 `G.inter` |
| 打完 boss 不捡掉落直接进传送门 | 传送门判定只要「存在」就短路所有拾取候选；要加「附近无值得捡的东西」门槛 |
| 冲刺撞刀臂/踩毒液/冲进虚空 | `dashSafe` 只看 PIT；敌方毒液在 `G.foeFx` 而非 `WORLD.pools` |
| 营地对话后整局冻结 | `startTalk()` 置 `G.state='talk'`，而没有对应 handler |
| `?v=` 版本参数 | 用户明确要求删除，接受 10 分钟 CDN 缓存 |
| 想忽略 `[TheSeed]` | gitignore 里 `[TheSeed]/` 是**字符类**语法，从未匹配到该目录；且不该忽略 |
| 单局跑分忽好忽坏 | 真方差，不是回归；多种子看均值 |
| 服务器根路径 404（`/` 打不开） | `join(ROOT, '/')` 得到目录，`stat` 判「非文件」→ 404。需显式映射到 `index.html` |
| bench 报 `no TSW_RESULT` 但游戏其实在跑 | 浏览器缺 `--no-sandbox --no-zygote --disable-dev-shm-usage`；容器里 zygote 起不来，页面脚本跑不到 emit |
| 批次之间数据自相矛盾（700 秒批次里出现 900 秒的行） | 两个批次共用 `runner.log` / `run-<seed>.log`，互相覆盖。用 `--tag` 隔离 |
| 某局跑满却不产出结果行 | 重试条件写成「退出码非 0」，但 bench 会 `exit 0` 且无输出；条件应只看「有没有产出结果」 |

## 排查顺序建议

1. 先看 `A.status.note` / `TSW.log` 有没有活动痕迹。
2. 再查 `window.__errs`（错误环）有没有异常。
3. 确认浏览器启动参数完整（见上表倒数第三条）。
4. 确认日志文件没有被另一个批次占用。
5. 最后才怀疑「是不是真的卡住了」——多次误判为卡死，实际是测量链路的问题。
## 测量与下结论时踩过的坑（这一列更值钱）

> 下面这些都是**我（AI）在分析时犯的错**，不是代码 bug。
> 共同点：**用一次测量就下结论，而那次测量缺了某个关键字段或条件。**

| 症状 | 真因 |
|---|---|
| 探针显示位置/敌人数「冻结」100 多秒 | **游戏已经死了**，而探针仍在按 interval 采样。必须记录 `g.state`，看到 `dead` 就停止采样 |
| A/B 两臂看起来有差异，换批重测就消失 | 两臂的**样本数不等**（如 4 vs 3），或某臂缺一整条结果。配对必须同种子、同数量、交错 |
| 以为某个 threshold 能区分，实测全过/全不过 | 阈值没落在**能力边界**上；且单种子的边界是陡的，必须**跨种子汇总**才有分辨率 |
| 二进制指标全同但连续指标有差 | 二值化把「差一点」和「差很多」压成同一档——**这是优点不是缺点**，说明阈值位置对了 |
| `runAB` 的 inner run 只有 9–16 游戏秒 | **同会话重复启动是坏的**（代码里早有此注释）。该工具的统计量可信，但样本不可用 |
| 以为「上限 10 波」，换参数后变成 5 波 | `runAB` 的 `base.wave` **默认是 9**（从第 9 波起跑），不是从第 1 波。**读默认值再下结论** |
| 同种子跑三次得到三种结局 | 虚拟时钟的起点在读真实时间（`performance.now()`）、`tickN` 未归一化、`virt` 是累加而非推导。三处都会泄漏绝对时间 |
| 同种子仍偶发不同（约 1/3） | 已修 8 个缺陷后**仍未定位**；`end`/`ticks` 已确定，`rooms`/`kills` 仍有分叉（§208） |
| `hp` 传 15/25/40 结果完全一样 | 存档 `s.hp` 上限 30，且最后被 `p.maxHp` 截断，而 `maxHp = 5 + S.maxHp`；唯一来源是 `vital` shard（`combat.js:45`，不在 `shards*.js`） |
| `startEndless()` 调了没反应 | 函数第一行 `if (G.endless) return;`，而 boost 存档里写了 `endless: 1`——**自己把入口关掉了** |
| 固定 `setTimeout` 等游戏就绪后仍偶发失败 | 冷页面上 `G` 不存在时调用会**静默失效**。要等具体状态（`g.state === 'play' && g.p`），不要等固定时间 |

## 下结论前的自检

```
1. 这条测量有没有记录足够的状态字段？（缺字段 = 可能误读）
2. 两臂是否同种子、同数量、交错执行？
3. 这是单个种子的结果，还是跨种子汇总？
4. 阈值是否落在能力边界上（有部分通过、部分不通过）？
5. 参数是我写的，还是某个默认值？（默认值算参数）
```
